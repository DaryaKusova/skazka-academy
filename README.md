# Сказка · Академия лидеров

Рабочая L&D-платформа: календарь, личные маршруты, практические задания, оценка навыков и гонка драконов. Светлая и тёмная темы, адаптивный интерфейс.

## Возможности

- Общая база Cloudflare D1; изменения доступны с разных устройств.
- Личный вход по логину и паролю. L&D выдаёт доступ каждому участнику; публичной регистрации нет. Email — необязательный контакт и не даёт права входа.
- Администратор L&D управляет программой, участниками, подтверждениями и правилами прогресса.
- Руководитель видит свой план, свои оценки и задачи. Общая гонка содержит имя, цвет, XP и прогресс, без раскрытия индивидуальных оценок.
- Редактор мероприятий: дата, тип, участники, тема, формат, результат, этап, комментарий. Архивирование сохраняет историю.
- Импорт JSON с предпросмотром и стабильными ID; подтверждения и оценки не заменяются данными планирования.
- Экспорт Excel (.xlsx) и Word (.docx): доступные данные, отбор календаря или отдельный ИПР. Семь основных листов Excel и семь дополнительных при наличии подробного ИПР. Генерация в браузере, без передачи данных сторонним сервисам. Сохранены CSV календаря и JSON рабочей области.
- Отдельные ИПР: период, основные цели, индивидуальные темы, общий рабочий маршрут, запросы, контрольные точки, сильные стороны и основания оценки. L&D заполняет и видит все планы, сотрудник читает личный. Назначенные действия, задачи и текущая карта навыков остаются отдельными разделами.
- Самооценка и внешняя оценка ИПР до 10 баллов с отдельными источниками. Они не усредняются, не заменяют карту навыков 0–5 и не начисляют XP. Пустые даты и оценки остаются неизвестными.
- Оценка выполнения задачи L&D по шкале 1–5 и отдельная обратная связь коллеги в общем групповом мероприятии. Сервер проверяет состав, автора, запрет самооценки и права чтения.
- Должности под ФИО и полный список назначенных участников своих групповых мероприятий. Общая гонка раскрывает только имя, должность и игровой прогресс.
- Одновременные правки защищены версией: устаревшее сохранение возвращает конфликт вместо потери данных.
- Карточки показателей на обзоре открывают подробности: участники — личные маршруты, мероприятия — календарь всего плана, выполнение — таблицу по участникам со ссылками на их маршруты.

## Конфиденциальность

В репозитории **нет** мастер-документа, списка сотрудников, оценок, секретов или производственной базы. Исходные данные импортируются отдельно в закрытые серверные API. Открытая страница входа не предоставляет доступ к данным. На уровне API права проверяются при каждом запросе.

## Учётные записи

Дарья сама задаёт логин и пароль администратора в локальной setup-форме. Действующие пароли не передаются в чат и не записываются в документацию. В «Кабинете L&D» администратор назначает участникам логины и пароли, а в пункте «Мой логин и пароль» меняет собственные данные входа.

Логин содержит 3–64 символа: латинские буквы, цифры, точку, дефис или подчёркивание; первый символ — буква или цифра. Регистр логина не учитывается. Пароль содержит 12–256 символов. Смена логина/пароля завершает прежние сессии соответствующего аккаунта. Приостановление участия лишает доступа к программе.

Пароли хешируются PBKDF2-HMAC-SHA-256 с индивидуальной случайной солью и 100 000 итераций, совместимыми с текущей средой Cloudflare Workers. Открытые пароли не хранятся. Серверные сессии действуют 7 дней; токены сессий в базе также представлены хешами. Cookie использует `HttpOnly`, `SameSite=Lax`, а в production — `Secure`. Запросы изменения проверяют источник; попытки входа ограничиваются по логину, IP и их сочетанию.

## Игровая модель

Предложенные настройки, которые администратор может изменить:

- 20 XP за подтверждённое участие в мероприятии.
- 30 XP за задачу, результат которой подтвердил L&D.
- 50 XP за один положительный балл роста навыка относительно стартовой оценки.
- 1000 XP до финиша; отображаемый прогресс ограничен 100%.

Повторная отметка не добавляет очков. Отсутствующая оценка хранится как `null`, а не как ноль. Пять игровых уровней не заменяют этапы программы. Суммарные XP не нормированы по количеству назначений и не являются основанием кадровых решений.


## Локальная разработка

Node.js >=22.13.0, npm. Стек: React 19, Vinext, Cloudflare Workers/D1, Drizzle, TypeScript.

```sh
npm ci
npm run build
node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0000_soft_avengers.sql
node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0001_purple_sway.sql
npm run dev
```

На чистой локальной базе откройте адрес dev-сервера с `/?setup=1`, например `http://127.0.0.1:5173/?setup=1`, и создайте кабинет администратора. Форма разрешена только в development на loopback и только до создания администратора. В production добавление `?setup=1` не открывает публичную регистрацию. Для обычного входа используйте назначенные логин и пароль; `ADMIN_EMAILS` для него не требуется.

Примените обе сохранённые миграции по порядку: `0000` создаёт рабочую область, `0001` — таблицы учётных записей, сессий и ограничений входа. `npm run db:generate` нужен при изменении схемы, а не для первоначального запуска готовой версии.

Если Windows-обёртка npm вызывает ошибку пути, используйте реальный Node и его `node_modules/npm/bin/npm-cli.js` либо `node scripts/run-framework.mjs build` / `dev`. Глобальную политику PowerShell менять не требуется.

## Production

Развёртывание предусмотрено через Sites. `.openai/hosting.json` содержит связь с проектом и binding `DB`; локальные и рабочие данные хранятся отдельно. Перед запуском версии с логином и паролем к рабочей базе необходимо применить обе миграции: `drizzle/0000_soft_avengers.sql` и `drizzle/0001_purple_sway.sql`. Этот документ описывает подготовленную реализацию и сам по себе не подтверждает публикацию обновлённой версии.

Runtime secrets:

- `ADMIN_EMAILS`: проверенный email владельца для отдельного административного восстановления через доверенную Sites-идентичность. Сотрудники входят по логину и паролю; контактный email не участвует в выдаче доступа. После настройки локальных учётных данных обычный вход не подменяется активной сессией Sites.
- `BOOTSTRAP_TOKEN`: одноразовый защищённый первичный импорт, минимум 32 случайных символа. Endpoint отказывает после первого импорта и не создаёт пользовательскую сессию. Первичный импорт также принимает проверенный снимок рабочей области с фактическими результатами. Вместе с программой он может атомарно перенести заранее созданную запись администратора с солью и хешем пароля; открытый пароль для этого не передаётся. После загрузки секрет можно удалить.
- `IPR_IMPORT_CONFIG`: временное разрешение на один заранее проверенный документ ИПР. Содержит хеш случайного токена, хеш канонического JSON и срок до 30 минут. `/api/plan-import` принимает только совпадающий документ, проверяет карточку и отказывает при существующем ИПР. Атомарно добавляет план и должность, сохраняя остальные данные; повторный запрос не перезаписывает план. После импорта секрет удаляют и применяют новую конфигурацию публикацией той же версии. API не создаёт сессии и не изменяет пароли. При отсутствии конфигурации импорт закрыт.

Не доверяйте заголовкам Sites-идентичности на произвольном хостинге: они предназначены для доверенного Sites dispatch. При переносе отключите или замените административное восстановление через Sites; собственный вход по логину/паролю должен работать через HTTPS и серверную базу сессий.

Рабочая область хранит JSON с атомарным CAS. Лимит документа 1.9 MB; при росте объёма следует перейти к отдельным таблицам. Журнал хранит последние 100 действий, а не полноценный архив версий. Текущая выгрузка JSON — средство резервного копирования; импорт программы не является полным восстановлением оценок из бэкапа.

## Подробный ИПР — 16.10.2026

Единая форма доступна в ИПР любого участника. L&D добавляет и изменяет строки шести разделов, период, источники и пары диагностических оценок. Сотрудник читает только свой план. Содержание личного образца загружается отдельно от исходного кода; пустой шаблон не копирует чужие цели и оценки.

62 автоматических теста проходят. Подробный ИПР проверен в браузере с изолированной SQLite: сохранение и перезагрузка, роль сотрудника, пустой шаблон, все колонки и отдельная шкала диагностики. Адаптивность проверена на 360, 390, 768 и 1440 px в светлой и тёмной темах; кнопка сохранения остаётся в границах диалога. Excel и Word скачаны в браузере и прочитаны openpyxl/python-docx; постраничная вёрстка Word отдельно не проверялась.
